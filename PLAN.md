# Plan

## Current state

- Both hooks, the `--sweep-only` mode and the `claude()` wrapper are implemented and in daily use.
- Marker semantics are final: mutually exclusive, replace-don't-stack, self-healing; marker == safe to delete; live sessions never marked.
- Provisional `[Dup?] ` marks land ~0.3s after a fork mint (roster info alone, job-row name only, before the settle wait); the same run's content sweeps upgrade or heal them, stragglers expire on the next full sweep, and a real verdict is never downgraded. NOT deletion-safe by design.
- A `←` inside a job-row marker best-guesses a left-press/backgrounding mint (parent was live around the mint: roster entry, or transcript written within 5 min before); it survives marker upgrades and drops on heal. Known limit: a fork minted at mint-time is indistinguishable from a fork the user then uses — divergence healing stays the truth-teller.
- Performance is settled: one-pass caches, US-separator loaders, sweep stamp, per-group containment matrix, end-anchored junk-tail reads, and skip-unchanged-since-last-sweep for content-driven verdicts — a steady-state sweep on a ~100MB tree runs well under a second (~10ms when the stamp is fresh).
- Write races are guarded: `%.Y` staleness check before every `state.json` write, in both hooks.
- Bare marker tokens inherited into ai-titles are neutralized to the short session id.
- In-flight writes are settled by per-file 100ms polling (3s cap); a file changing on 5 polls is declared streaming immediately, so an active session never stalls the sweep.
- Duplicate verdicts, marker healing and the session-end supersede check judge by the last conversation uuid whenever the raw tail is locally-minted junk (attachments, system-reminder-only entries, "No response requested." fillers).
- Post-review hardening (external review 2026-10-02): same-target and sync elections rank only by unmutated inputs (own-session row, unmarkedness, roster startedAt, folder — never tool-bumped mtimes); rescue is fill-only (never replaces beyond an ai echo); repair checks both roster keys, requires an hour-silent non-liveish parent, and retries when a candidate ages past the settle window on a quiet tree; is_liveish also matches live workers by roster launch source. Known accepted costs: sync re-reads the ai-title of protected (hand-renamed) targets each sweep; a permanently unrepairable named dead row keeps the parent-lookup greps on busy-machine sweeps.
- Second hardening round (external review + self-review, 2026-10-02): pid_matches_start no longer compares the /proc starttime against a positional parameter that `set --` had already clobbered — the old comparison silently declared every recorded worker dead, voiding ALL live-session protection on a real roster (markers on live rows/transcripts, lost election priorities, broken sweeps_current exemptions); caught only because the fixture roster used dead pids exclusively. Also: the same-target election's live-worker tier now checks the row FOLDER roster key too (a live repaired row no longer loses to a fresher-startedAt rival), rescue skips is_liveish parents like sync and repair do, the sync election's recency tier uses roster startedAt instead of tool-bumped J_MTIME, the provisional sweep sanitizes startedAt before arithmetic, and the repair skip also voids itself when any transcript crosses the hour-silence line with no write (a parent aging into eligibility on a quiet tree is retried, not stranded). fwtest.sh now really asserts (fail counter, exit 1) with live-pid/wrong-starttime/live-copy/live-repaired-row fixtures and a repair-gate aging test; verified by mutation (re-breaking pid_matches_start fails exactly the four live-worker assertions).
- Row repair shipped (the one exception to append/rename-only): a user-named [Dead]/[Stub] row whose conversation survives in an unmarked continued-in parent is repointed at it (sessionId/resumeSessionId/linkScanPath) with its name healed; refused when another servable row reaches the parent; verified live 2026-10-02.
